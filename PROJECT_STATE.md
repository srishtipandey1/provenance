# Project State

## Goal
- Provenance compares declared engineering structure with public contribution behavior using deterministic FalkorDB tools and replayable evidence.
- The LLM only selects typed tools and narrates verified facts; deterministic mode requires no LLM.
- Hackathon tracks: Agents That Act on Connected Data; Agent Memory and Coordination; Company Brain.

## Data And Graph
- Public Home Assistant `core` and `architecture` data is loaded in `provenance_ha`; no private GitHub data is stored.
- Core labels: Person, Team, Module, PR, Decision. Event times are integer Unix seconds; ownership and dependency edges are current snapshots.
- Loader uses the official FalkorDB client, indexed lookup keys, parameterized UNWIND batches, and read-only GRAPH.RO_QUERY reads.
- Python-import scan produced 4,467 import edges; total DEPENDS_ON edges: 5,152.

## Deterministic Tools And Agents
- Eight registered tools: module_profile, ownership_drift, bus_factor, blast_radius, criticality, suggest_reviewers, maintainer_loss, decision_trace.
- Tool facts retain registered query IDs/params and original node/edge IDs; verifier replays evidence and checks grounded claims.
- Deterministic router and provider-agnostic LLM agent use typed tools only; no free-form Cypher is generated by the LLM.
- Track 2 graph state: Task, Episode, and synthetic Agent nodes with CLAIMED_BY, PRODUCED, USED_FACT, and Task DEPENDS_ON relationships.
- ReviewerAgent recommends from a PR; RiskAgent composes ownership drift, bus factor, and criticality; HistorianAgent retrieves its prior Episode from FalkorDB.
- `scripts/coordination_demo.py` runs the workflow and demonstrates persisted history; no added LLM calls.
- `scripts/tenant_demo.py` copies selected modules and their mutual dependency links plus associated PR/person slices into two isolated graphs, routes the same question, checks separate task state, then deletes both graphs.
- `scripts/concurrency_demo.py` submits 20 parallel writes to an existing graph; its Task/Episode records remain persisted.

## API And Dashboard
- Read-only FastAPI endpoints cover health, tools, deterministic/LLM ask, tool execution, risk, scoreboard, search, and bounded neighborhoods; details are in `docs/api.md`.
- React/Vite dashboard uses same-origin `/api`, shows verified claims and graph evidence, and supports risk/module cross-navigation.

## Evaluation
- Reviewer round-two pooled unseen B/C (n=2,812): B3 hit@3 0.4257, G1 0.4772, G3 0.5441; G3 is a top-K improvement, not a universal hit@1 win.
- Text RAG pooled per-PR-as-of B+C (n=2,812): hit@1/3/5, recall@5, MRR = 0.343/0.569/0.684/0.603/0.488; G3 and RAG have different strengths by slice.
- Detailed results remain in `results/reviewer_eval_round2.json`, `results/reviewer_eval_round2_per_pr.json`, `results/rag_baseline.json`, and `results/scoreboard.json`.

## Verification And Limits
- Full suite command: `.venv\Scripts\python.exe -m pytest -q --basetemp .pytest-temp`.
- Graph-dependent tests use temporary graphs and skip with a Docker startup hint when FalkorDB is unavailable; tests never start Docker.
- Tenant demo graphs are deleted on exit. Concurrency demo intentionally leaves probe records in the chosen graph.
- `AI_USE.md` records AI assistance; `DECISIONS.md` records schema/query choices.
