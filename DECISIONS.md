# Design Decisions
Every schema, query, and architecture decision in plain language: what, why, and the alternative rejected.

- Docker Compose runs the official `falkordb/falkordb` image, publishes the database and Browser ports (6379 and 3000), and mounts a named volume at `/var/lib/falkordb/data` as documented by FalkorDB. This keeps development data persistent; a host bind mount was not chosen because the project needs portable local persistence.
- Gate 0 reads declared ownership from integration manifests and applies the last matching top-level CODEOWNERS rule to each integration's manifest path; this avoids rescanning every integration subtree and makes the ownership comparison reproducible. ADR metadata is extracted from local text files. GitHub PR sampling uses GraphQL search filtered by merged date and updated-time ordering, requesting files and reviews with 100-item nested limits. GitHub does not expose mergedAt as a pull-request connection sort key, so updatedAt is the ordering proxy; the full-fetch estimate assumes the observed mean cost and latency per page.
- PR ingestion uses the repository pullRequests connection ordered by UPDATED_AT, not the capped Search API. It stops once updatedAt is older than the stored UTC cutoff and independently retains only records whose mergedAt is in-window. Pages are appended as JSONL before atomically advancing the cursor state; cached PR numbers are deduplicated to make replay after interruption safe. The first/retry page size starts at 50 and is halved after timeout or node-limit failures. PR body text is capped at 6,000 characters and redacts email addresses and GitHub token-shaped strings to honor the data-handling rules.
- PR cache records store the GraphQL `body` field rather than `bodyText` so raw Markdown checkbox state is preserved for later surveys. The body remains capped at 6,000 characters and redacted. `__typename` is retained on `mergedBy` and review authors so bot actors can be distinguished without inferring from login names.
